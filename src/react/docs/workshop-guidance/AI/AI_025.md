# Configure AI destination, source-type, and HTTP-method filtering

**Implementation Effort:** Medium - Requires defining destination rules, supported source conditions, policy assignments, and a pilot scope.  
**User Impact:** Medium - Restricted destinations or methods can disrupt legitimate AI applications and agent workflows.

## Overview

Global Secure Access (GSA) web content filtering controls access by web category, URL, and fully qualified domain name (FQDN). Source traffic type and HTTP-method conditions can further distinguish agent traffic from user traffic and restrict selected operations.

These controls support *Use least privilege access* by limiting reachable services and *Verify explicitly* through policy decisions on acquired traffic. They turn an approved-AI-services policy into network controls, but do not replace application authorization.

### Prerequisites

- Complete [AI network readiness](./AI_163.md), including acquisition for the intended traffic source.
- Internet Access licensing, the required GSA administrative roles, and current feature/client support.
- An approved AI-service inventory and agreed exceptions with business and data owners.
- Transport Layer Security (TLS) inspection where HTTPS method or supported source inspection requires it.

### Limitations

- Agent/User source conditions require supported client metadata; remote networks do not support this condition. Do not assume client classification applies to Copilot Studio.
- Without TLS inspection, HTTPS filtering is limited to Server Name Indication (SNI)-based rules rather than the payload-level inspection required for method conditions.
- HTTP methods do not fully describe tool intent: POST, for example, can represent either read or write operations.
- Root-domain and wildcard coverage must be considered separately. URL filtering has a documented tenant limit of 1,000 URLs.
- Copilot Studio uses the supported [baseline policy path](./AI_027.md).
- Destination filtering does not inspect sensitive prompt content or restrict individual Model Context Protocol (MCP) tools. Those require complementary [network data loss prevention (DLP)](./AI_192.md) and [MCP firewall controls](./AI_191.md).
