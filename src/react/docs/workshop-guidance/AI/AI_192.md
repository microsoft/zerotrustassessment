# Protect Sensitive AI Prompts and Files with Purview Network DLP

**Implementation Effort:** Medium - Jointly configure acquisition, content inspection, Purview DLP, policy assignment, and monitoring.  
**User Impact:** Medium - Sensitive content can be blocked; inspection limits and false positives need operational handling.  
**Documentation checked:** 2026-11-11  

## Overview

Global Secure Access (GSA) content policies can use **Scan with Purview** to inspect supported files and text for Microsoft Purview DLP decisions. This protects sensitive prompts and file transfers involving unmanaged/cloud AI applications and goes beyond blocking a destination or checking whether a file has a sensitivity label.

Purview Network Data Security supports text sent/received and files uploaded/downloaded, subject to the integration's capabilities. The GSA integration supports sensitive information, labels, and user-risk-related conditions through its policy model.

This supports *Use least privilege access* for data movement and *Assume breach* by adding inline data-loss controls on eligible traffic.

## Prerequisites

- Complete [AI_163](./AI_163.md), including acquisition and TLS inspection.
- Appropriate GSA/Purview administrative roles and licensing. For the GSA integration, licensing options include Microsoft 365 E7 or Purview E5/equivalent plus Entra Internet Access/equivalent; verify applicable entitlements against the linked licensing guidance.
- Traffic must map to an **Entra user identity**. Agent-only, anonymous, or unmapped traffic is not automatically eligible.
- Joint network/data-protection ownership, approved sensitive-information test data, and a pilot scope.

## Implementation guidance

1. Define prohibited data-sharing scenarios, destinations, and activities with data owners.
2. Configure or review Purview DLP policies for the applicable network/unmanaged cloud app scenarios. Use collection policies where discovery is required; collection alone is not blocking.
3. Under **Global Secure Access > Secure > Content policies**, create rules for target destinations and supported file/text types, selecting **Scan with Purview**.
4. Link the content policy to a security profile and follow the documented client/user Conditional Access assignment path.
5. Verify eligible user identity, destination matching, TLS inspection, and Purview policy scope.
6. Test sensitive prompts and files, benign content, supported response/download scenarios, and known uninspectable cases.
7. Monitor GSA outcomes and **PurviewStatus**, and use Purview DLP alerts/Activity explorer for investigation.

## Validation and completion evidence

- Synthetic sensitive text/file content is blocked under the intended policy; benign content is allowed.
- GSA transactions and Purview evidence correlate for inspected cases.
- Oversized/uninspectable and identity-unmapped cases are documented with monitoring and compensating controls.
- Privacy, retention, exceptions, and triage responsibilities are assigned.

## Scope and limitations

- Scan with Purview supports content up to **3 MB** for both files and text; OCR is not supported.
- Oversized payloads or inspection errors can **fail open**. Use PurviewStatus to identify skipped inspection.
- API rate-limit exceedance is documented separately as fail-closed; do not conflate it with Purview inspection failures.
- Encoded/chunked file transfers can evade supported file detection. WebSocket file-type filtering is bypassed, although text type is still evaluated.
- Basic Allow/Block content rules do not create Purview investigation records.
- Do not assume Copilot Studio baseline traffic or autonomous agents are Purview-scanned without proving the required user-identity mapping and feature support.
