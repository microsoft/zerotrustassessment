# Restrict AI Egress Destinations, Ports, and Protocols with Cloud Firewall

**Implementation Effort:** Medium - Define source-specific acquisition, firewall rules, profile selection, and regression tests.  
**User Impact:** Medium - Incorrect acquisition or broad block rules can interrupt AI workloads and unrelated internet access.  
**Documentation checked:** 2026-11-11  
**Feature status:** Client cloud firewall and broad wildcard acquisition are documented as preview; remote-network firewall has a separate guide.  
**Applicability:** Optional extension for acquired client/branch egress needing network-layer controls.

## Overview

AI tools can use direct-IP connections, nonstandard ports, or protocols outside ordinary web filtering. Global Secure Access (GSA) cloud firewall can allow or block acquired connections using supported destination, port, and protocol conditions.

**Acquisition and firewall enforcement are separate.** A firewall rule does not cause its traffic to be forwarded. Default Acquire covers TCP 80/443; other traffic requires an appropriate acquisition design.

This supports *Use least privilege access* by restricting egress and *Assume breach* by limiting outbound connections after a device or agent is compromised.

## Prerequisites

- Complete [AI_163](./AI_163.md); identify the client versus remote-network source.
- Appropriate Internet Access licensing, GSA administrative access, and client Conditional Access access where applicable.
- Review preview availability/approval, existing acquire modes, SWG coexistence, and recovery access.
- Inventory required destinations, ports, protocols, and IPv4/IPv6 paths.

## Implementation guidance

1. Use the configuration guide for the intended traffic source: clients or remote networks. Do not apply remote-network limitations wholesale to the separate client preview.
2. For client nonstandard-port/UDP scenarios, configure Custom Acquire for the required destinations, ports, and protocols. Preserve required bypasses and existing coverage. Do not assume Agentic Acquire covers this traffic.
3. Create a cloud firewall policy. Its documented default is **Allow**; use explicit **Block** rules to restrict traffic rather than assuming a policy-level default-deny setting exists.
4. Define reviewed Allow/Block rules with unique priorities and the supported matching conditions. Conditions within a rule are combined with AND. New rules are disabled by default; confirm enabled status deliberately.
5. Prepare required exceptions before attaching a broad block policy.
6. For clients, link the firewall policy to a security profile and follow the client guide's Conditional Access assignment. Profile selection is not cumulative: the selected applicable profile's firewall decision is terminal.
7. For remote networks, use the baseline attachment and five-tuple capabilities documented for that source. Destination FQDN rules are not supported in the remote-network guide.
8. Test matching and nonmatching ports/destinations, direct-IP access, and approved recovery paths.

## Validation and completion evidence

- Diagnostics prove the tested connection is acquired, including nonstandard-port traffic where claimed.
- An approved connection succeeds and a prohibited connection is blocked with the intended rule/profile.
- Default-Allow residual access and direct-IP/IPv6 coverage are explicitly assessed.
- Policy propagation, bypasses, and rollback are documented.

## Scope and limitations

Private Access routing takes precedence and is not evaluated by Internet Access cloud firewall rules. Broad `0.0.0.0/0` acquisition covers IPv4, not IPv6.

The client preview does not acquire/filter DNS queries. QUIC acquisition/blocking does not imply supported end-to-end QUIC forwarding. Client FQDN matching requires a destination name and does not substitute for IP restrictions.

Cloud firewall is not payload-level DLP or MCP tool authorization. The remote-network page's statement that clients are unsupported conflicts with the dedicated client-preview guide; use the latter only for the documented client preview.
