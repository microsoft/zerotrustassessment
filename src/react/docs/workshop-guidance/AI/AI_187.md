# Discover remote MCP servers and observed tool usage with Global Secure Access

**Implementation Effort:** Medium - Requires checking traffic forwarding, inspection and log access, then matching an approved MCP session to its recorded events.
**User Impact:** Low - The discovery check observes traffic without adding a blocking policy. New traffic-forwarding or inspection deployments need separate compatibility testing.

## Overview

Agents can connect to remote Model Context Protocol (MCP) servers that expose tools and resources. An approved agent can therefore reach a server the security team has not reviewed. Knowing which tools a server advertises is also different from knowing which tools an agent actually invokes.

Global Secure Access MCP logging inspects the protocol to identify remote MCP traffic, including previously unknown servers. Review the logs in **Global Secure Access > Monitor > Generative AI Insights** in the Entra admin center. Filter **Activity = MCP** to review the captured events.

Two acquisition paths are documented. **End-user devices** need the Global Secure Access client, Internet Access traffic forwarding and TLS inspection. **Copilot Studio agents** use the dedicated Global Secure Access integration, which logs this traffic without requiring TLS inspection. Do not apply the device inspection procedure to that integration. Use **Global Secure Access Administrator** access for configuration and the documented **Global Secure Access Log Reader** permissions for log access.

Validate with an approved remote endpoint and a harmless read-only tool call using non-sensitive arguments. Review `initialize` and `tools/list` events for advertised capabilities, and `tools/call` request/response events for actual invocations. Use **Destination URL**, rather than client or server display names, as the reliable server identifier. Match request and response using **Event ID**, group related events by **Session ID**, and use **Transaction ID** to connect them to the network traffic record.

Record the destination, observation time, supported identity context and a correlated tool-call result. Redact payloads before sharing evidence. Do not infer a unique agent identity from a logged user alone or mark the check complete because the dashboard is available. If the expected session is missing, investigate traffic acquisition and collection with an accountable owner.

Only remote traffic captured through the supported route is visible. Local stdio MCP servers have no inspectable remote network footprint; use [Defender local-agent discovery](./AI_186.md) for the complementary configuration view. Neither missing network events nor a configured MCP entry proves that no tool activity occurred.

This supports *Verify explicitly* through observed server and tool activity, and *Assume breach* by exposing unreviewed connections. Use the findings to inform approval and least-privilege decisions. Logging itself does not block a server or tool; configure and test any required enforcement separately.
