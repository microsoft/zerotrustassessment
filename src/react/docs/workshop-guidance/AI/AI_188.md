# Restrict Entra agent identity blueprint creation to approved creators

**Implementation Effort:** Low - Requires reviewing a tenant setting, confirming approved creator access and testing allowed and denied creation attempts.
**User Impact:** Medium - Ordinary users may need an approved creator role or an administrator-assisted route to create new blueprints.

## Overview

Agent identity blueprints are reusable templates for creating Entra agent identities. Controlling who can create them helps organizations establish accountability before new agents are introduced, rather than discovering unmanaged identities after deployment.

By default, users can create agent identity blueprints. The **Users can create agent blueprints** setting allows administrators to remove this default permission. When set to **No**, creation is restricted to authorized administrators and users with the **Agent ID Developer** role. Use that delegated role for approved creators rather than granting routine Global Administrator access.

In the Entra admin center, use **Cloud Application Administrator** access to open **Entra ID > Users > User settings** and review the setting. Before changing it, identify legitimate creators and agree an onboarding route with development teams. Delegate access through the authorized role-assignment process; permission to change the tenant setting does not itself grant permission to assign roles.

Where the organization's policy requires restricted creation, set **Users can create agent blueprints** to **No** and save. Validate with two approved test users: an authorized creator who can create an accountable test blueprint, and an ordinary user without inherited creator or administrator privileges who cannot. Record the setting, tested roles, authorization results and timestamps, then remove disposable test objects through the supported process.

Review existing blueprint ownership, application-permission paths and source-platform authoring permissions separately. This switch does not remove existing ownership, approve agent publication, grant runtime permissions or restrict every way of building an agent. Do not change unrelated app-registration or consent settings simply to complete this check.

This supports *Use least privilege access* by limiting identity creation to approved people and *Verify explicitly* by testing both the permitted and denied paths. A working delegated route is as important as the restriction: developers should not need broad administrator privileges to follow the approved process.
