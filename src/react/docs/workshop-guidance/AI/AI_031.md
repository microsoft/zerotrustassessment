# Extend prompt injection protection to custom JSON-based AI endpoints

**Implementation Effort:** Medium - Requires mapping each application's request format and maintaining the extraction configuration as it changes.  
**User Impact:** Low - Approved requests should remain functional, but incorrect mappings or detected threats can cause blocks.

## Overview

Custom AI applications can wrap model APIs or expose prompts through request formats that built-in conversation schemes do not recognize. Global Secure Access (GSA) supports custom schemes based on the destination service URL and the prompt's JSON path.

Extending the existing [prompt-protection policy](./AI_029.md) supports *Verify explicitly* by identifying the actual request field being inspected. It supports *Assume breach* by reducing gaps at custom application boundaries.

### Prerequisites

- Complete [Prompt Injection Protection configuration](./AI_029.md), including its client, forwarding, Transport Layer Security (TLS), profile, and Conditional Access prerequisites.
- Internet Access acquires the endpoint traffic, and the application is eligible for the feature.
- An application owner can provide endpoint URLs, representative request schemas using synthetic data, and a safe test environment.
- Ownership is assigned for endpoint/schema changes, exceptions, and extraction maintenance.

### Limitations

- Custom schemes map the request prompt, not an arbitrary model-response JSON schema. This control does not provide general response inspection.
- Coverage is specific to each mapped URL and request format; one working route does not establish coverage for the entire application.
- Supports JSON-based applications and text prompts only. Prompts beyond 64,000 characters are truncated, and rate-limit exceedance causes blocking.
- Private endpoints are not automatically covered by Internet Access or by adding a scheme. Non-JSON, multimodal, file, and unacquired traffic require other controls.
