# Verify Global Secure Access readiness for AI workloads

**Implementation Effort:** Low - Assess existing infrastructure and identify prerequisites; missing deployments are separate work.  
**User Impact:** Low - Readiness assessment does not change traffic routing or enforcement.

## Overview

AI network protection depends on a supported traffic path and the appropriate enforcement policy for each source. Microsoft Entra Internet Access can protect supported endpoint, remote-network, and Copilot Studio traffic, but those sources do not share identical prerequisites or feature support.

This readiness checkpoint supports *Verify explicitly* by identifying what each control can cover before rollout. It supports *Assume breach* by exposing bypasses and unsupported paths rather than treating agent registration or policy creation as proof of protection.

### Prerequisites

- An inventory of AI sources, destinations, ports, protocols, identity context, and accountable owners.
- Licensing, administrative access, tenant availability, and supported client/environment configurations for the selected features.
- Source-appropriate acquisition: [Agentic Acquire](./AI_190.md) for applicable local agents or [Copilot Studio forwarding](./AI_022.md) for supported hosted interactions.
- Network and data-protection owners for shared [threat-intelligence filtering](../network/NET_039.md), [network content policies](../network/NET_038.md), exceptions, change approval, and recovery.

### Limitations

- Acquisition forwards traffic; it does not itself enforce an Allow or Block decision. Policies also require the correct attachment and supported inspection path.
- Transport Layer Security (TLS) inspection is required for encrypted payload inspection, but not every destination control. Server Name Indication-based HTTPS filtering can operate without decryption; Copilot Studio Model Context Protocol (MCP) logging has a separate integration path.
- Scan with Purview requires eligible traffic mapped to an Entra user identity. Agent-only or anonymous traffic is not automatically scanned.
- Bypasses, other gateways, certificate-pinned applications, and unsupported transports can affect coverage. Private Access and private networking require separate assessment.
- This task identifies readiness and gaps; it does not declare every AI flow protected or deploy missing controls.
