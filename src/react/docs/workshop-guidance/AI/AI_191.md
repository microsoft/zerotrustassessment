# Restrict Remote MCP Servers and Tools with Global Secure Access MCP Firewall

**Implementation Effort:** Medium - Inventory approved servers/tools, configure protocol-aware policy, and validate agent compatibility.  
**User Impact:** Medium - Blocked MCP servers or primitives can prevent agent tasks from completing.  
**Documentation checked:** 2026-11-11  
**Feature status:** Preview.  

## Overview

The Global Secure Access (GSA) MCP firewall inspects supported Model Context Protocol traffic between clients/agents and remote MCP servers. It can allow or block servers and individual primitives such as tools, resources, and prompt templates, with conditions including methods, protocol versions, and transport.

This adds protocol-aware least privilege beyond allowing a destination domain. An approved MCP server can expose both permitted and prohibited tools.

This supports *Use least privilege access* through server/tool restrictions and *Assume breach* by limiting what a compromised client can invoke through the protected path.

## Prerequisites

- Complete [AI_163](./AI_163.md); obtain approval for preview deployment.
- Internet Access licensing, Global Secure Access Administrator, and Conditional Access Administrator access.
- MCP firewall requires a supported GSA client on an Entra joined/hybrid-joined device or VM, Internet Access forwarding, and TLS inspection. Confirm the platform/device combination against the prerequisites in the linked configuration guide.
- An approved server/tool inventory and safe remote MCP test server.

## Implementation guidance

1. Discover remote MCP usage through [remote MCP discovery](./AI_187.md), and classify servers/tools with application and data owners.
2. Under **Global Secure Access > Secure > MCP policies (Preview)**, create a policy with an explicitly chosen default action.
3. Prefer a reviewed approved-server/tool model for sensitive use. Configure server URL conditions and necessary tool/resource/prompt restrictions.
4. Add protocol-version, method, and transport restrictions where required. Do not assume an allowed host makes every primitive safe.
5. Link the MCP policy to a security profile. Follow the documented Conditional Access assignment targeting **All internet resources with Global Secure Access** for pilot users.
6. Test the actual MCP client/agent. Validate discovery/list responses and invocation behavior rather than relying solely on policy visibility.
7. Monitor network transactions and MCP events in Generative AI Insights; retest when server tool inventories change.

## Validation and completion evidence

- An approved server and tool work.
- A prohibited server is blocked.
- A prohibited tool on an otherwise approved server is blocked.
- The observed decisions correlate with network and MCP telemetry.
- Default action, exceptions, support boundaries, and rollback are documented.

## Scope and limitations

Inspects remote MCP using JSON-RPC 2.0 over streamable HTTP and Server-Sent Events. Local/stdio servers and JSON-RPC batches are not inspected.

During preview, configured primitives may not be displayed when rules are reopened in the UI. Verify them through Microsoft Graph using the steps in the linked configuration guide.

This does not replace MCP OAuth/token validation or application authorization. It complements the APIM gateway requirement in this workshop's AI_077 control. Do not infer Copilot Studio policy-enforcement parity from its MCP logging support.
