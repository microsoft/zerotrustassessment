# Govern generative AI apps by risk and enforce access decisions

**Implementation Effort:** Medium - Requires risk review, enforcement integrations, and an understanding of device coverage.  
**User Impact:** Medium - Blocked applications require sanctioned alternatives and a documented exception process.

## Overview

Microsoft Defender for Cloud Apps provides cloud-app discovery, risk information, and Sanctioned/Unsanctioned classifications. Those decisions become access controls only when connected to an enforcement mechanism.

This supports *Verify explicitly* by connecting application risk to approved use and *Assume breach* by reducing access to unapproved services. Align these decisions with [Global Secure Access destination filtering](./AI_025.md) so the organization does not maintain conflicting allow/block policies.

### Prerequisites

- Existing AI app discovery and an agreed risk, approval, and exception process.
- Licensing for Defender for Cloud Apps and the selected enforcement product.
- For Microsoft Defender for Endpoint enforcement: supported onboarded devices, administrative access, cloud/network protection settings, and the documented integration prerequisites.
- An inventory of unmanaged, unsupported, or otherwise unenforced devices and traffic paths.

### Limitations

- An Unsanctioned tag alone does not provide universal blocking. Defender for Endpoint integration, supported security-appliance integration, or an exported block list provides the enforcement path.
- Unsanctioned decisions can take up to three hours to propagate to endpoint blocking.
- Domain-based blocking does not provide application-layer inspection, prompt data loss prevention, or coverage for every agent host.
- Browser, operating-system, endpoint-protection, and integration support determine actual coverage. Unmanaged or unsupported paths need separate ownership and compensating controls.
