# Acquire Local AI Agent Web Traffic with Global Secure Access

**Implementation Effort:** Medium - Select the acquisition mode, verify clients/SWG coexistence, and pilot routing and enforcement.  
**User Impact:** Medium - Routing changes or policy blocks can affect local agents and, if other acquire modes are disabled, existing user coverage.  
**Documentation checked:** 2026-11-11  

## Overview

**Agentic Acquire** is an Internet Access forwarding policy that signals the Global Secure Access (GSA) client to acquire web traffic originating from local AI agents, such as GitHub Copilot CLI and Claude CLI. It supports deploying GSA for local-agent protection alongside another Secure Web Gateway (SWG) handling other user traffic.

It is distinct from enabling GSA for hosted Copilot Studio environments. Acquisition establishes the traffic path; separate web, prompt, content, DLP, and MCP policies determine supported enforcement.

This supports *Verify explicitly* by establishing and testing the agent's real network path and *Assume breach* by reducing otherwise unmonitored local-agent egress.

## Prerequisites

- Complete [AI_163](./AI_163.md), including licensing, Global Secure Access Administrator access, pilot users, and bypass review.
- Agentic Acquire supports Windows and macOS with minimum GSA client versions **2.31.125** and **1.1.26030604**, respectively. Recheck these minimums in the linked configuration guide before deployment.
- Agree ownership and routing with existing SWG/VPN administrators.
- Confirm whether full or selective Internet Access acquisition already meets the requirement. Agentic-only acquisition is not mandatory if existing forwarding is verified.

## Implementation guidance

1. Inventory local agents and their destinations. Define whether the goal is agent-only acquisition or broader Internet Access protection.
2. Review all current acquire/bypass policies, assignments, and traffic relying on them. Obtain change approval before disabling existing acquisition.
3. For the documented agentic-only configuration, browse to **Global Secure Access > Connect > Traffic forwarding**, open Internet Access policies, and select **Create Agentic Acquire**, or enable the existing policy.
4. Following the documented agentic-only setup, disable **Custom Acquire** and **Default Acquire**. Do not apply this step to an existing broad deployment without an approved replacement for affected traffic coverage.
5. Confirm Internet Access profile enablement and intended user/group assignments.
6. Attach the supported enforcement policies for the pilot. Configure TLS inspection separately where required.
7. Exercise each representative local agent and compare with ordinary user/browser traffic and the other SWG's telemetry.

## Validation and completion evidence

- Agent web requests are acquired by GSA and correlated with the expected source/destination.
- A supported policy blocks a controlled prohibited request while approved agent use succeeds.
- Ordinary user traffic follows the intended route without a protection gap.
- Bypasses, unrecognized agents, unsupported flows, and rollback are documented.

## Scope and limitations

Agentic Acquire supports **local-agent web traffic** on Windows/macOS. This does not imply coverage of all protocols, all processes, every agent, remote-network classification, or hosted-agent traffic. Do not assume it acquires nonstandard-port/UDP traffic for [cloud firewall](./AI_193.md); plan acquisition for that scenario separately.

Agent registration is not acquisition, and acquired traffic is not automatically inspected or denied.
