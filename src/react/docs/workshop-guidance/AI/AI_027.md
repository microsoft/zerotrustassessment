# Activate baseline security policies for Microsoft Copilot Studio agent traffic

**Implementation Effort:** Low - Requires attaching approved policies once supported routing is established.  
**User Impact:** Medium - Baseline changes can affect supported agent traffic and other Internet Access traffic across the tenant.

## Overview

Microsoft Copilot Studio's Global Secure Access (GSA) integration uses the baseline security profile to enforce supported network policies. Creating filtering policies or enabling forwarding alone does not apply those policies to agent traffic.

Baseline activation supports *Verify explicitly* by making acquired interactions subject to policy decisions. It supports *Assume breach* by reducing unfiltered paths within the integration's supported scope. Policy attachment belongs in the same controlled rollout as policy creation, not a later optional optimization.

### Prerequisites

- [Copilot Studio forwarding](./AI_022.md) is enabled.
- [Existing custom connector routing](./AI_023.md) is updated where those connectors are present.
- Applicable web, threat-intelligence, and content policies have been reviewed for the intended traffic.
- A nonproduction environment, recovery procedure, and owner for tenant-wide policy impact.

### Limitations

- Conditional Access-linked security profiles are not supported for the Copilot Studio integration.
- The baseline profile can affect other tenant traffic; an agent-specific rollout does not eliminate that wider impact.
- This requirement is specific to the Copilot Studio path. Client-based prompt protection, Model Context Protocol (MCP) firewall, and client cloud firewall use their own documented profile and assignment paths.
- A policy's availability in GSA does not prove support for every Copilot Studio interaction. Large language model orchestration calls are excluded from forwarding, and Scan with Purview has a separate Entra user-identity requirement.
