# Configure automated lifecycle policies for Microsoft Entra Agent ID

**Implementation Effort:** Medium - Requires defining policy scope, lifecycle rules, notifications and actions, then testing the policy with agent sponsors.
**User Impact:** Medium - Disabling or deleting an agent identity can interrupt the agent and the business processes that depend on it.

## Overview

Agent identities can remain active after their work ends or the people responsible for them leave. These forgotten identities may retain access to organizational resources without anyone reviewing whether that access is still needed. Lifecycle policies help organizations keep agent identities accountable and retire those that no longer meet their requirements.

Microsoft Entra Agent ID lifecycle policies provide three rules: **Periodic reconfirmation** checks that an agent is still needed, **Minimum sponsor requirement** checks that it has enough sponsors, and **Inactivity monitoring** identifies identities that have not received authentication tokens within a defined period. Different policies can cover different groups of agents. When scopes overlap, the highest-priority matching policy applies.

Administrators configure these policies in **ID Governance > Lifecycle Workflows > Lifecycle Policies > Agent ID (Preview)** in the Microsoft Entra admin center. A violation of any enabled rule starts the configured notification and enforcement process. Actions include disabling the identity, soft-deleting it, or disabling it before later deletion. Review grace periods and the deletion delay so representatives have an appropriate opportunity to respond.

Sponsors or owners can use the **Manage agents** experience to reconfirm needed agents or address missing sponsorship. Configure fallback notification recipients for identities without an accountable representative. Notifications alone do not prevent retirement: the underlying violation must be addressed within the configured timeframe.

Configuration requires **Lifecycle Workflows Administrator** or **AI Administrator** access.

The feature is in preview and is not recommended for production workloads. Validate with **Specific agents** in a nonproduction pilot, starting with **Disable** rather than deletion. Confirm notification delivery, sponsor responses and the resulting identity state after the applicable timeframes. A saved policy is not proof of enforcement. The companion [Manage inactive agents](./AI_185.md) task covers inactivity testing in more detail.

This supports *Verify explicitly* through recurring confirmation of purpose and accountability, *Use least privilege access* by retiring identities that should no longer authenticate, and *Assume breach* by reducing unattended identities. These controls govern Entra agent identities; they do not replace Agent 365 registry management, resource-permission reviews or incident containment.

### Configure custom Entra Agent ID lifecycle policies

Different agents may need different reviews and retirement rules. A temporary project agent, for example, may need more frequent checks than a long-running business agent. Custom Microsoft Entra Agent ID lifecycle policies let administrators define these requirements instead of relying only on the fixed default inactivity policy.

A custom policy can contain **Periodic reconfirmation**, **Minimum sponsor requirement** and **Inactivity monitoring** rules. These check whether an agent is still needed, has enough sponsors and has received authentication tokens within the configured interval. Enable the rules that match the business requirement; a violation of any enabled rule can trigger the policy.

Configure policies in **ID Governance > Lifecycle Workflows > Lifecycle Policies > Agent ID** in the Entra admin center, using **Lifecycle Workflows Administrator** or **AI Administrator** access. Start with **Specific agents** containing only approved test identities. Choose **Disable**, **Delete** (soft deletion), or **Disable and delete**, and review remediation grace periods and any subsequent deletion delay.

Sponsors and owners receive notifications so they can reconfirm a needed agent or address missing sponsorship through **Manage Agents**. Configure fallback recipients for identities without an accountable representative. Review overlapping scopes: the highest-priority matching custom policy applies, while the [default inactivity policy](https://learn.microsoft.com/en-us/entra/id-governance/agent-default-inactivity-policy) is evaluated last.

Validate in a nonproduction pilot, starting with **Disable**. Confirm notification delivery, sponsor responses and the resulting identity state. Reconfirmation testing requires at least a 30-day interval.

This supports *Verify explicitly* through recurring confirmation of purpose and accountability, *Use least privilege access* by retiring identities that should no longer authenticate, and *Assume breach* by reducing forgotten access. These policies govern Entra agent identities; registry management, resource-permission reviews, sponsor mover/leaver workflows and source-platform cleanup remain separate controls.
