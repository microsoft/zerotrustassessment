# Manage inactive agents

**Implementation Effort:** Medium - Requires reviewing agent activity, choosing an inactivity threshold and testing the policy with agent owners.
**User Impact:** Medium - Disabling or deleting an inactive identity can interrupt a legitimate workload that runs infrequently.

## Overview

Agents created for completed projects or temporary tasks can leave behind identities that still have access to organizational resources. Without a retirement process, these identities remain an unnecessary security risk. However, an agent that runs only occasionally may still be needed, so inactivity should be reviewed against its business purpose before deciding to retire it.

The **Inactivity monitoring** rule in Microsoft Entra Agent ID lifecycle policies identifies identities that have not received authentication tokens for longer than a configured duration. This is identity authentication activity, not language-model token consumption. Choose a threshold that fits the workload schedule; a gap in available telemetry is not proof that an identity is unused.

Configure the rule under **ID Governance > Lifecycle Workflows > Lifecycle Policies > Agent ID (Preview)** in the Microsoft Entra admin center. Review the agent scope, action, notification recipients and grace periods. Check that the highest-priority matching policy contains the inactivity rule. If other rules are also enabled, identify which rule caused a violation rather than attributing every outcome to inactivity.

Accountable representatives receive notifications so they can decide whether an agent should remain active. A needed agent can be exercised through its approved workload; verify fresh identity-token issuance rather than relying on sponsor acknowledgment alone. If the violation is not addressed, the policy can disable the identity, soft-delete it, or disable it before later deletion. An owner or administrator must help re-enable a disabled identity; sponsors cannot do this themselves.

Configuration requires **Lifecycle Workflows Administrator** or **AI Administrator** access.

The feature is in preview and is not recommended for production workloads. Use a small nonproduction pilot with an active and an inactive test identity, starting with **Disable**. Record activity evidence, notifications and the resulting identity state. Keep checks pending until the required time has elapsed and outcomes are confirmed. Disabling an identity is not proof that every existing agent session has ended.

This supports *Verify explicitly* by checking ongoing business need against identity activity, *Use least privilege access* by retiring unjustified identities, and *Assume breach* by reducing unattended access. It complements [automated lifecycle policies](./AI_184.md), focusing on inactivity rather than sponsor reconfirmation or registry cleanup.
