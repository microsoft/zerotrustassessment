# Discover local AI agents with Microsoft Defender for Endpoint

**Implementation Effort:** Medium - Requires checking device onboarding, supported Defender versions and permissions, then confirming that expected agents appear in the inventory.
**User Impact:** Low - Discovery collects inventory information. It does not block agents or change their access.

## Overview

Local AI agents run on employee devices and can connect to tools and services. An inventory focused only on cloud agents can miss these installations. Security teams need to know which local agents are present, which devices and accounts they are associated with, and how they are configured before deciding how to manage them.

Microsoft Defender for Endpoint discovers supported local AI agents on onboarded Windows and macOS devices. Where supported, it also identifies their configured Model Context Protocol (MCP) servers. Results appear in **Assets > AI agents > Local agents** in the Microsoft Defender portal, with device, account and agent details. An agent installed on several devices or used by different accounts can have multiple inventory entries.

Use onboarded devices in a supported commercial-cloud environment and check the required Defender versions. The operator needs **Security data basics (Read)** permission with **Security for AI** as a data source in Defender unified RBAC.

The discovery method depends on the agent. Process-based discovery detects a running agent process; a successful sign-in or prompt is not required. Certain supported VS Code extensions can be inventoried without running the extension or requiring active-mode antivirus, provided the Defender client is running and reporting. Process-based discovery and MCP configuration collection still require active-mode Defender Antivirus and real-time protection. Check the support matrix for requirements and supported coverage.

Validate discovery using an approved, supported agent on a known test device. Confirm that its inventory entry matches the expected device, account and version, and review configured MCP servers where supported. Record the discovery time and any coverage gaps. If a result is missing, work with the endpoint team to check onboarding, reporting and prerequisites rather than assuming the agent is absent.

This supports *Verify explicitly* by connecting agent installations to device and account context, and *Assume breach* by helping security teams identify unexpected local agents and tools. The resulting inventory informs ownership, approval and least-privilege reviews; discovery itself does not apply those controls.

This complements Intune-based Shadow AI discovery and the Agent 365 registry, rather than replacing them. A discovered installation does not prove successful service use, native Entra Agent ID or runtime protection. Likewise, a configured MCP server is not evidence that a tool was invoked.
