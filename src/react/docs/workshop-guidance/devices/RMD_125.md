# 125: WSUS to Autopatch

**Implementation Effort:** High  
**User Impact:** Medium

## Overview

Moving from WSUS-centric patching to Microsoft Intune, Windows Update for Business, and Windows Autopatch shifts update management from manually curated on-premises approval to policy-driven cloud servicing. In a Zero Trust model, that change matters because update compliance becomes easier to scale for remote devices, security patches move faster, and device health can be evaluated without requiring users to return to the corporate network.

## Implementation Guidance

1. Inventory the current Windows update estate first. Identify which devices are governed by WSUS, Configuration Manager, Intune, or manual policy, and record any dependencies on on-premises approval workflows.
2. Move update authority intentionally. If devices are co-managed, decide when the Windows Update workload transfers to Intune and how conflicting policies will be removed.
3. Design update rings for test, pilot, broad production, and high-sensitivity populations. Define quality-update cadence, feature-update cadence, emergency patch handling, and whether Autopatch will manage one or more rings.
4. Use Windows Autopatch where it fits your support model, but document the service expectations, roles, and reporting approach. Autopatch still requires admin oversight and business communication.
5. Include driver, firmware, and safeguard-hold strategy in the rollout. Update maturity is not just monthly quality patches.
6. Monitor compliance and failure data continuously so stuck devices, low-storage devices, and incompatible hardware are addressed early.
