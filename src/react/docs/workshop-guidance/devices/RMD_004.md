# 004: Scope Tags

**Implementation Effort:** Medium – Requires taxonomy definition and cleanup of existing Intune objects.

**User Impact:** Low – The impact is on administrator visibility, not on end users.

## Overview
Scope tags determine which Intune objects an administrator can see and manage. They are essential for distributed administration because they let a regional or business-unit admin work only with the policies, profiles, apps, and scripts intended for that segment. In Zero Trust, scope tags reduce unnecessary visibility into unrelated administrative objects and help keep management authority compartmentalized.

## Implementation Guidance
1. Choose a small, durable set of tags that reflect real delegation boundaries such as region, subsidiary, or support service line.
2. Apply tags consistently to policies, scripts, applications, and other objects that should stay within that boundary.
3. Use scope tags together with scope groups and RBAC role assignments; a tag by itself does not define what actions an admin may take.
4. Document who is allowed to create new tags. Uncontrolled tag creation often leads to overlapping models and weak governance.
5. Audit for untagged objects regularly and fix them before they become the path of least resistance for unintended visibility.
6. Include scope-tag validation in operational runbooks for new policy deployment.
