# 151: Proactive Remediations

**Implementation Effort:** Medium — scripting is powerful but requires change control, testing, and ownership to avoid creating unmanaged drift.

**User Impact:** Low to Medium — good remediations are invisible to users, but bad scripts can cause disruption quickly.

## Overview
The feature commonly known as Proactive Remediations is now presented as Remediations in Microsoft Intune. It allows administrators to run paired detection and remediation scripts on managed devices so common configuration drift, health issues, and low-risk support problems can be corrected automatically. In a Zero Trust program, Remediations can help sustain required device state between policy refreshes, but they should complement formal configuration management rather than replace it.

## Implementation Guidance
- Establish script governance first. Every remediation should have an owner, source control, testing history, approval path, and clear rollback plan.
- Use detection logic that is explicit and safe. The detection script should identify a known issue precisely, and the remediation should make the smallest reliable corrective change.
- Pilot new remediations on limited device rings and review logs before moving to broad production assignment.
- Avoid using Remediations as a hidden workaround for policy design problems. If a setting belongs in a compliance policy, configuration profile, security baseline, or app package, manage it there instead.
- Capture output and operational telemetry so repeated failures can be investigated and so successful remediations can be measured for business value.
- Review and retire old remediations periodically so the environment does not accumulate orphaned scripts that no one remembers.
