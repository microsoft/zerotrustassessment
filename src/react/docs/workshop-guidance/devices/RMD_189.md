# 189: Setup Notification and monitoring of Service Health Dashboard

**Implementation Effort:** Low
**User Impact:** Low — users are not directly impacted by setup, but good monitoring shortens outages and confusion.

## Overview
Operations teams should monitor Microsoft 365 service health so they can quickly determine whether device enrollment, policy delivery, app deployment, or compliance outages are service-side rather than tenant misconfiguration. A documented monitoring path reduces duplicate troubleshooting and preserves visibility into critical control-plane dependencies.

## Implementation Guidance
1. Assign an operations owner for Microsoft 365 service health and define escalation paths for Intune, Microsoft Entra, Windows Update, and Apple-management dependencies.
2. In the Microsoft 365 admin center, review Service health and Message center settings and configure incident notifications for the teams that own Intune operations and user communications.
3. Decide which alerts go to email, Teams, or an incident platform and make sure after-hours coverage exists for high-severity issues.
4. Pair service health monitoring with tenant monitoring such as enrollment failures, policy assignment failures, and Conditional Access sign-in trends.
5. Review Message center posts regularly to catch retirements, portal changes, and service notices that affect device management guidance.
