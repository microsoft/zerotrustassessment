# 142: Feature Updates

**Implementation Effort:** Medium — setting a target version is simple, but app readiness, hardware readiness, and rollback planning require coordination.

**User Impact:** Medium — feature updates can change UI, platform behavior, and app compatibility for end users.

## Overview
Feature update policies in Microsoft Intune let you target approved Windows versions so devices move to, or stay on, the release your organization has validated. This is an important Zero Trust operating control because devices should remain both secure and supportable; unmanaged drift onto unsupported or untested versions increases security and operational risk. Feature update policies work alongside update rings, readiness testing, and Windows release-health monitoring.

## Implementation Guidance
- Choose target versions based on support lifecycle, hardware readiness, line-of-business app validation, and any regulatory or business blackout periods.
- Create feature update policies for distinct device populations if some business areas need to stay on a different validated release for a limited time.
- Use pilot deployments first and monitor safeguard holds, compatibility issues, and unsupported hardware before expanding scope to broad production.
- Coordinate target-version changes with application owners, service desk communications, and user readiness resources so the rollout is not only technically successful but operationally absorbed.
- Do not use feature update policy as a substitute for monthly patching. Continue to manage quality updates through update rings, expedited updates, or Windows Autopatch where appropriate.
- Review Windows release health and support milestones regularly so devices do not remain pinned to versions approaching end of servicing.
