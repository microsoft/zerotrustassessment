# 057: Apple Managed Accounts

**Implementation Effort:** Medium to High

**User Impact:** Medium

## Overview
For personally owned Apple devices, organizations can use **account-driven user enrollment** to provide a lighter-touch management experience that respects personal privacy while still protecting work data. Separately, **Managed Apple IDs** and Apple Business Manager federation can improve how Apple services and identity align with Microsoft Entra ID.

A Zero Trust design should be explicit about which problem is being solved: identity alignment with Apple services, BYOD enrollment with limited management, or both.

## Implementation Guidance
1. Confirm that BYOD users truly need device enrollment rather than only **app protection policies**. If app-level protection is sufficient, MAM-only may provide a better privacy and user-experience balance.
2. If you need Apple BYOD enrollment, evaluate **account-driven user enrollment** and confirm prerequisites such as Apple Business Manager support, supported OS versions, Microsoft Authenticator requirements, and any **just-in-time registration** prerequisites documented by Microsoft.
3. If Managed Apple IDs are part of the design, coordinate with the Apple Business Manager administrators to configure federation and identity lifecycle processes.
4. Create the enrollment profile in the **Microsoft Intune admin center**, target a pilot group, and validate sign-in, app deployment, and removal of work data at unenrollment.
5. Communicate the privacy boundary clearly: user enrollment gives the organization limited management of the work context, not full control of the personal device.
6. Test how the enrollment model interacts with Conditional Access, required apps, certificate delivery, and per-app VPN if those features are in scope.
