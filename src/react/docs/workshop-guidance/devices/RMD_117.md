# 117: Deploy Entra Join Only

**Implementation Effort:** Medium to High  
**User Impact:** Medium

## Overview

Microsoft Entra join is the preferred join model for many new Windows corporate devices because it removes routine dependence on on-premises domain controllers and aligns naturally with Microsoft Intune, Conditional Access, and cloud-first identity controls. In a Zero Trust design, Entra-joined devices are easier to evaluate continuously, easier to provision remotely, and better aligned to modern app, update, and compliance policies.

## Implementation Guidance

1. Use Entra join as the default for new corporate Windows devices unless a documented dependency still requires hybrid join. Make that default explicit in architecture standards, procurement guidance, and Autopilot profiles.
2. Validate prerequisites before rollout: Microsoft Intune licensing, Windows edition support, enrollment restrictions, device naming standards, local administrator strategy, and the user sign-in experience.
3. Integrate Entra join with Windows Autopilot where possible so devices can be shipped directly to users and provisioned without imaging or domain-join task sequences.
4. Map access to remaining on-premises resources before migration. Many organizations can use modern approaches such as cloud identity integration, Kerberos-related cloud trust patterns, or resource modernization instead of preserving broad domain dependence.
5. Apply baseline compliance, endpoint security, update, and app policies early so the device is governed from first sign-in rather than after a long post-build process.
6. Pilot with remote and branch-office users, not only headquarters staff. Cloud-native value is highest when the join model works well away from corporate networks.
