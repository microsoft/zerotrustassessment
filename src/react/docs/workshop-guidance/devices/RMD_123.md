# 123: File Shares to Cloud

**Implementation Effort:** High  
**User Impact:** High

## Overview

Traditional SMB file shares often assume users are on trusted networks or connected through broad VPN access. A Zero Trust endpoint program should reduce that dependency by moving collaboration and personal productivity storage to cloud services where identity, device compliance, auditing, sharing, and data protection are easier to enforce. For many organizations, that means using SharePoint Online for team content, OneDrive for Business for personal work files, and Azure Files only where an application or legacy workflow truly requires file-share semantics.

## Implementation Guidance

1. Classify file-share use cases before migrating anything. Separate team collaboration, personal work files, application back-end shares, profile data, and highly regulated repositories because they rarely belong on the same destination platform.
2. Use SharePoint Online for shared team documents and OneDrive for Business for user-owned work files whenever the workflow is document collaboration rather than legacy application hosting.
3. Use Azure Files selectively for workloads that still require file-share protocols or application compatibility. Do not move everything to Azure Files by default if the real need is modern document collaboration.
4. Plan identity, permissions, and sharing carefully. Cloud storage modernization is not just a copy operation; you must redesign access models, external sharing, retention, and data loss prevention requirements.
5. Update user workflows and endpoints together. Offline sync, browser access, document coauthoring, Teams integration, and mobile access should be part of the rollout plan, not an afterthought.
6. Keep a documented exception list for remaining on-premises shares and review it regularly so the organization continues reducing legacy dependencies.
