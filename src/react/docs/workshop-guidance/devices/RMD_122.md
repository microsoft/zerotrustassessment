# 122: GP Preferences

**Implementation Effort:** High  
**User Impact:** Medium

## Overview

Group Policy Preferences often represent the hidden operational glue of a traditional Windows environment: drive mappings, printers, scheduled tasks, registry tweaks, local group membership, and shortcuts. When moving to cloud-managed devices, these settings should be reviewed one by one rather than copied blindly. Some have modern Intune equivalents, some should move to scripts or platform-native cloud services, and some should be retired entirely because the original use case no longer exists.

## Implementation Guidance

1. Inventory which GPP items are actually in use today and who depends on them. Preferences are often inherited for years without active ownership, so usage validation is essential.
2. Map each preference to one of four outcomes: replace with an Intune-native control, replace with a cloud service, handle with a script or remediation, or retire. For example, local group membership can often move to endpoint security account protection, while legacy printers may move to Universal Print.
3. Be cautious with drive mappings and file-share shortcuts. These often point to the broader need to modernize identity, storage, or application workflows rather than recreate an old logon script pattern.
4. Use scripts or remediations sparingly and only where there is no better platform-native control. If a script is needed, document ownership, rollback, and telemetry so it does not become invisible technical debt.
5. Validate user impact in pilots. GPP migration failures usually show up as missing drives, printers, tasks, or local rights that users relied on silently.
6. Delete retired preference logic after cutover so administrators can tell whether a behavior is still intentional.
