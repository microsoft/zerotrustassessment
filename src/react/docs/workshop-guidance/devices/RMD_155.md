# 155: Review logs using Azure Monitor in Microsoft Intune

**Implementation Effort:** Medium — exporting and retaining logs is easy to start, but useful monitoring requires workspace, access, query, and cost planning.

**User Impact:** Low — end users are generally unaffected because the control is administrative and back-end focused.

## Overview
Streaming Intune diagnostic data into Azure Monitor helps organizations centralize device-management visibility, investigate issues faster, and correlate Intune events with Microsoft Entra sign-ins, Microsoft Defender alerts, and broader SOC monitoring. In a Zero Trust program, this supports the “assume breach” principle because administrators can detect drift, identify failing protections, and investigate suspicious management activity instead of relying only on the Intune portal's short-term operational views.

## Implementation Guidance
- Decide which destination best fits your operating model: Log Analytics for investigation and alerting, Event Hubs for SIEM forwarding, Azure Storage for archival, or a combination of those options.
- Enable the relevant Intune diagnostic settings and document which log categories are required for security operations, operational troubleshooting, audit, and compliance reporting.
- Apply RBAC and retention settings deliberately. Log data often contains device names, user context, configuration outcomes, and potentially sensitive operational details.
- Build a starter query pack or workbook for common investigations such as failed policy assignments, repeated compliance-state changes, enrollment failures, and suspicious administrative activity.
- Correlate Intune data with Microsoft Entra ID, Microsoft Defender, and incident-response tooling so device-management events contribute to end-to-end investigations rather than sitting in isolation.
- Review ingestion volume and cost regularly, especially if you export broad diagnostic sets into a large Log Analytics workspace.
