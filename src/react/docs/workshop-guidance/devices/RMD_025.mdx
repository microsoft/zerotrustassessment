# 025: Data protection framework using App protection

> **Implementation Effort:** Medium  
> **User Impact:** Medium

## Overview
Microsoft publishes a data protection framework for Intune app protection policies so organizations can phase controls based on risk. This is useful for Zero Trust because it lets you start with a practical baseline for all mobile users, then add stronger controls for sensitive roles or higher-risk data.

To operationalize the framework effectively, administrators should map each user population to Level 1, Level 2, or Level 3 and define which policy controls tighten between each level.

## Implementation Guidance
1. Define user populations first:
   - **Level 1 / Basic**: broad mobile workforce
   - **Level 2 / Enhanced**: users handling confidential data
   - **Level 3 / High**: highly targeted roles, privileged or regulated populations
2. Build separate Intune app protection policies for each level rather than one policy with many exceptions.
3. Use Level 1 to establish the minimum Zero Trust baseline, such as:
   - Require PIN or biometric-backed app access where appropriate
   - Restrict copy/paste from managed to unmanaged apps
   - Prevent saving organizational data to personal storage locations
4. Use Level 2 to increase resistance to data leakage and outdated clients, such as stricter data transfer settings, shorter offline grace periods, and stronger launch requirements.
5. Use Level 3 for the highest-risk roles, often including aggressive data movement restrictions, tighter version requirements, and stricter response actions when risk conditions are detected.
6. Align each level with Microsoft Entra Conditional Access so cloud access requirements and app protection requirements reinforce each other.
7. Publish support documentation that explains what users should expect when moving between levels.

Treat the framework as a living standard. Reassess it when new app protection capabilities appear, when business units adopt new mobile apps, or when your threat model changes.
