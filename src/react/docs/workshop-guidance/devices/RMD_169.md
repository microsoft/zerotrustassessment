# 169: Scripts

**Implementation Effort:** Medium  
**User Impact:** Low to Medium

## Overview

Scripts in Intune are a gap-closure tool for configuration and remediation tasks that are not yet available through native policy settings. On Windows, PowerShell scripts and related remediation workflows can help enforce standards, collect information, or fix drift when used carefully.

From a Zero Trust perspective, scripts should be used sparingly and governed tightly. A script can strengthen device trust, but it is also executable code running at scale on endpoints, which makes review, scoping, signing, and rollback planning important.

## Implementation Guidance

### Prefer native controls when possible
- Use settings catalog, endpoint security, compliance, and application management features first; use scripts only when Intune does not natively expose the required outcome.
- Define the exact purpose of each script, its expected output, the execution context, and its owner.
- Avoid using scripts as a permanent substitute for a well-supported product feature if a native control becomes available later.

### Develop and deploy safely
- Test scripts on isolated pilot devices and validate 32-bit versus 64-bit execution behavior, rerun behavior, and logging before broad assignment.
- Use the Intune management extension where required and confirm it is healthy on target devices.
- Separate detection logic from remediation logic when using remediation-style workflows so support teams can understand why a device was changed.

### Operate with change control
- Version-control every script, require peer review, and maintain a rollback plan for failures.
- Review execution status, device logs, and helpdesk tickets after deployment to catch unintended side effects quickly.
- Remove or replace scripts that become obsolete so the environment does not accumulate hidden configuration dependencies.
