# 027: RBAC

> **Implementation Effort:** Medium  
> **User Impact:** Low for end users; Medium for admins

## Overview
Role-based access control (RBAC) in Microsoft Intune is how you limit administrative permissions so that support staff, security teams, regional IT, and specialist administrators can perform only the actions they need. In a Zero Trust model, Intune administration should be explicitly scoped, monitored, and minimized.

Intune RBAC works together with Microsoft Entra roles, scope tags, scope groups, and privileged access controls such as Privileged Identity Management to form a complete least-privilege operating model.

## Implementation Guidance
1. Start with an administrative role matrix. Define who needs read-only access, help desk actions, policy management, device configuration rights, application management rights, and tenant-wide control.
2. Use built-in Intune roles where they fit, but create custom roles when you need to remove high-risk permissions.
3. Scope assignments carefully with:
   - **Scope groups** to limit which users/devices an admin can manage
   - **Scope tags** to limit which objects are visible and manageable
4. Avoid long-lived standing access for high-privilege roles. Where possible, require just-in-time elevation through Microsoft Entra Privileged Identity Management.
5. Separate policy authoring from approval and broad deployment if your organization uses change-control or multi-admin approval processes.
6. Review role assignments quarterly and after organizational changes.
7. Audit for overprivileged accounts, shared admin accounts, and assignments that unintentionally bypass regional or business-unit boundaries.

The most common RBAC failure is not missing a role, but granting broad tenant-wide permissions for convenience. This should be treated as a design problem, not an operational shortcut.
