# 178: Deploy MDM based policies for EDR/AV

**Implementation Effort:** High  
**User Impact:** Low to Medium

## Overview

A successful macOS EDR and antivirus deployment is not only about installing Microsoft Defender for Endpoint. Intune must also deliver the required management profiles that approve extensions, grant privacy permissions, and enable background capabilities so the security client can function correctly.

From a Zero Trust perspective, these MDM-delivered policies are part of the trust chain. If the client is installed but lacks the required permissions or onboarding state, the organization may overestimate the device's security posture.

## Implementation Guidance

### Build the prerequisite profile set
- Identify the required macOS profiles for system extensions, network extensions or filters, notifications, full disk access, and other Defender prerequisites.
- Keep the prerequisite profiles logically separated so support teams can identify which permission failed without editing one monolithic profile.
- Validate whether existing privacy or restrictions profiles from other teams could conflict with the new security deployment.

### Sequence the deployment
- Assign the prerequisite profiles before or alongside the Defender app deployment so devices do not require repeated user interaction.
- Deploy the onboarding or EDR-specific policy only after the app and permission profiles are healthy on pilot devices.
- Use phased groups to validate enrollment timing, policy application, and reporting before expanding beyond the pilot.

### Confirm security readiness
- Check that devices are onboarded successfully in Microsoft Defender and that the Intune profile results show success for each prerequisite.
- Review alerts, health reports, and device inventory to catch partially configured endpoints.
- Update the profile set when Microsoft or Apple changes the required permissions for new product versions.
