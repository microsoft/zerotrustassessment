# 132: MDM based policies for Wi-Fi

**Implementation Effort:** Medium — secure Wi-Fi deployment usually requires coordination between Intune admins, network engineers, and PKI owners.

**User Impact:** Medium — users benefit from seamless connection to corporate wireless, but incorrect SSID, EAP, or certificate settings can block connectivity.

## Overview
Wi-Fi profiles in Microsoft Intune let administrators deploy consistent wireless settings to managed devices so users can connect securely without manually entering configuration details. In a Zero Trust program, Wi-Fi profiles matter because they can enforce stronger authentication methods, reduce reliance on shared passwords, and pair with certificate-based access so only approved users and devices join sensitive networks.

## Implementation Guidance
- Document each wireless scenario separately: employee corporate Wi-Fi, shared-device Wi-Fi, guest access, and any special-purpose SSIDs such as warehouse or kiosk networks.
- Prefer certificate-based authentication such as EAP-TLS for enterprise wireless where possible; if you do, deploy trusted root and client certificate profiles before the Wi-Fi profile.
- Create platform-specific Wi-Fi profiles in the Microsoft Intune admin center and define the SSID, authentication method, proxy settings, and whether the network should connect automatically or only when in range.
- Align Wi-Fi design with network segmentation: devices that fail compliance or device health requirements should not continue to receive the same level of network access as compliant devices.
- Pilot with multiple hardware vendors and roaming scenarios, because adapter drivers, captive portals, certificate stores, and saved profile precedence can all affect user experience.
- Monitor profile deployment and create a rollback plan so you can quickly remove a bad profile without leaving users stranded.
