# 128: Office Apps

**Implementation Effort:** Medium — app assignment is simple, but update channel, removal of legacy versions, and VDI considerations require planning.

**User Impact:** Medium — users depend heavily on Microsoft 365 Apps, so install timing, app set, sign-in state, and update channel choices affect productivity.

## Overview
For Windows endpoints, Microsoft 365 Apps for enterprise is a core managed application workload. Intune can deploy the application suite, control which apps are installed, standardize the update channel, and integrate app servicing with broader device management strategy. In a Zero Trust context, keeping Microsoft 365 Apps current and deployed only to supported, managed devices helps reduce exploit exposure and supports consistent identity and data-protection behavior.

## Implementation Guidance
- Use the dedicated Microsoft 365 Apps app type in Intune for standard deployments rather than treating the suite as a generic package.
- Decide which apps should be included, what update channel is appropriate, whether to remove older Office versions automatically, and whether shared computer activation is required for virtualized or shared scenarios.
- Assign the app as required or available based on user role and device ownership, and coordinate install timing with other major provisioning steps such as Autopilot, configuration baselines, and VPN or browser setup.
- Separate application deployment from policy decisions for macros, add-ins, OneDrive sync, Outlook profiles, and Teams behavior; those usually belong in additional configuration policies rather than the app object itself.
- Monitor installation status, app health, and update compliance, especially when devices are remote or subject to bandwidth restrictions.
- Document exception handling for line-of-business add-ins and legacy compatibility dependencies before broad rollout.
