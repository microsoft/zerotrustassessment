# 092: Wi-Fi

**Implementation Effort:** Medium  
**User Impact:** Low to Medium

## Overview
Wi-Fi profiles in Microsoft Intune let administrators push wireless network settings to managed devices so users can connect securely without manually typing SSIDs, secrets, or certificate parameters. This is especially important for corporate networks where strong authentication and repeatable configuration matter.
For Zero Trust, Wi-Fi should not rely on broad shared secrets when certificate-based methods are available. A well-designed Wi-Fi profile reduces configuration drift, supports least privilege on internal networks, and works as part of a larger compliant-device access model.

## Implementation Guidance
1. Prefer enterprise-grade authentication such as WPA2-Enterprise or WPA3-Enterprise with EAP-TLS when your environment supports it.
2. Deploy trusted root, intermediate, and client certificate profiles before the Wi-Fi profile if the network uses certificate-based authentication.
3. Create separate profiles for different network purposes, such as corporate secure Wi-Fi versus guest access, rather than overloading one profile with multiple expectations.
4. Avoid hidden SSIDs unless there is a clear operational requirement, because they add complexity without providing meaningful security by themselves.
5. Pilot across the exact device modes you support, including BYOD work profile, fully managed, shared devices, and devices that roam between sites.
6. Monitor connection failures after certificate renewal, password rotation, or wireless infrastructure changes.
