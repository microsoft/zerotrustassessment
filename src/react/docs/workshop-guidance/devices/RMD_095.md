# 095: Web app deployment

**Implementation Effort:** Low  
**User Impact:** Low

## Overview
Web app deployment in Intune usually means publishing a managed shortcut to a business web application or internal portal so users can find and launch it easily from a managed experience. This can be useful for intranet sites, SaaS portals, or lightweight apps that do not justify a full native mobile package.
In Zero Trust terms, publishing the shortcut is only part of the control. You also need to define which browser is supported, how sign-in works, whether the site requires a compliant device, and whether access to private resources depends on an additional control such as Microsoft Tunnel or another secure access method.

## Implementation Guidance
1. Decide whether the target should open in a managed browser such as Microsoft Edge and whether browser policy is needed to protect session data, downloads, and link handling.
2. Create the web app or web link in Intune with a clear name, icon, and audience so users understand what business purpose it serves.
3. Apply Conditional Access appropriate to the site: compliant device, approved client app, MFA, or other grant controls based on the sensitivity of the resource.
4. If the web app is private, verify the access path before rollout. Some sites need Microsoft Tunnel or another private-access pattern rather than a plain internet browser launch.
5. Pilot on the exact mobile platforms and enrollment types you support, validating SSO, redirection, deep links, file handling, and session timeout behavior.
6. Review usage and support tickets after rollout to determine whether the web experience is sufficient or whether a native or private app pattern is needed later.
