# 006: Organizational Messages

**Implementation Effort:** Low to Medium – Basic setup is simple, but good message targeting and governance require coordination with communications and endpoint teams.

**User Impact:** Medium – Users see branded prompts, reminders, or educational notices on managed endpoints.

## Overview
Organizational messages let administrators publish first-party notifications and in-product messages to users on supported Microsoft-managed experiences. While this is not a core enforcement control like compliance policy or Conditional Access, it can support Zero Trust adoption by communicating enrollment deadlines, app migration, passwordless onboarding, or device hygiene expectations directly to end users. Used well, it reduces confusion during rollout of endpoint security controls.

## Implementation Guidance
1. Define which device-security changes genuinely benefit from an end-user communication campaign, such as enrollment deadlines, app migration, passwordless registration, or mandated updates.
2. Align message content with the approved security change and the target audience. Keep messages short, action-oriented, and consistent with official support channels.
3. Target messages carefully so only affected users see them. Broad generic messages quickly become background noise and reduce trust in future notices.
4. Coordinate timing with Intune rollouts. Messages should appear before or alongside a required action, not weeks after users are already impacted.
5. Establish ownership for content approval, localization, and retirement. Old messages should be removed once the change window closes.
6. Measure support tickets, adoption rates, or enrollment completion before and after the campaign to determine whether the messaging improved rollout quality.
