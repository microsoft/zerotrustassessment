# 141: Update Rings

**Implementation Effort:** Medium — defining update governance, pilot groups, and exception handling is more work than creating the policy itself.

**User Impact:** Medium — update timing, restart rules, and deferrals directly affect user experience and business continuity.

## Overview
Windows update rings in Microsoft Intune determine how quality updates and core servicing behaviors are delivered to managed Windows devices. In a Zero Trust program, keeping devices current is essential because unpatched endpoints quickly become weak trust anchors. Update ring settings help balance security speed with business continuity by defining restart behavior, active hours, deferrals, deadlines, and rollout cadence.

## Implementation Guidance
- Create clear deployment rings such as test, pilot, broad production, and critical or exception populations. Ring design should reflect both business impact and device diversity.
- Configure update ring settings deliberately, including deadlines, grace periods, automatic behavior during active hours, driver handling, and user notification experience.
- Use Windows Autopatch when you want Microsoft-managed ring orchestration and servicing operations for supported device populations, but still document which devices are in or out of scope.
- Combine update rings with feature update policies and expedited quality update policies rather than trying to solve every servicing need with one policy object.
- Monitor update success, safeguard holds, paused deployments, and recurring failure patterns so you can adjust rings without losing control of patch latency.
- Maintain a formal pause and rollback decision process for bad updates, including communications, time limits, and business-owner approval paths.
