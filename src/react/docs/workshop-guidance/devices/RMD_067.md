# 067: LoB app Deployment

**Implementation Effort:** Medium to High

**User Impact:** Medium

## Overview
Line-of-business (LOB) app deployment in Microsoft Intune is used for internally developed or privately distributed apps that are not delivered through the public App Store. In a Zero Trust context, LOB apps deserve extra scrutiny because the organization is effectively acting as the publisher, which means signing, update hygiene, and access control are all your responsibility.

A secure LOB deployment process should be predictable, well-documented, and tightly integrated with identity and data-protection policy.

## Implementation Guidance
1. Confirm that the app package is signed correctly for enterprise distribution and that the signing process has an owner and a renewal plan.
2. In Intune, add the iOS/iPadOS **line-of-business app** package and review the discovered metadata before assigning it.
3. Define the deployment intent: pilot, required, or available. Internal apps should almost always go through a pilot ring before broad rollout.
4. If the app handles organizational data, pair deployment with **app configuration**, **app protection**, or Conditional Access controls where the app architecture supports them.
5. Document the update and retirement process. Internal apps often fail operationally when the signing certificate changes or when an old build remains assigned too long.
6. Test installation, upgrade, rollback expectations, token or identity sign-in, and behavior during unenrollment.
