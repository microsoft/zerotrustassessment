# 124: Apps Delivery / App Compatibility

**Implementation Effort:** High  
**User Impact:** Medium

## Overview

App delivery and app compatibility decisions are central to Zero Trust device security because applications are how users reach data and privileged workflows. A modern Microsoft Intune strategy should make approved apps easy to find and update, restrict unapproved installation paths, and provide a governed process to test compatibility before broad release. The objective is not only to deploy apps, but also to make the approved app path safer and simpler than unmanaged alternatives.

## Implementation Guidance

1. Create an application taxonomy: Microsoft Store apps, Win32 apps, line-of-business packages, web apps, Microsoft 365 Apps, Apple apps, and Managed Google Play apps. Different packaging types need different ownership and update models.
2. Define a trusted app catalog and approval workflow. Admins and app owners should know how new apps are requested, vetted for security and privacy, packaged, tested, and retired.
3. Use deployment rings for new or updated apps. Test first with IT and business champions, then broader pilot groups, then production, especially for security agents, browser add-ins, VPN clients, and productivity suites.
4. Plan app compatibility explicitly for both Windows and mobile. Include OS version support, architecture requirements, licensing, dependencies, and whether the app needs elevated rights or legacy network access.
5. Reduce local admin dependency. Standard users should be the norm, with exception handling through approved tooling such as Endpoint Privilege Management where appropriate.
6. Monitor install success, version drift, and failure causes. Packaging quality and detection rules matter as much as the decision to assign the app.
