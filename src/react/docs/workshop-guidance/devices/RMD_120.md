# 120: Autopilot Pre-provisioning

**Implementation Effort:** Medium to High  
**User Impact:** Low to Medium

## Overview

Windows Autopilot pre-provisioning is useful when you want to shorten the end-user setup experience by completing much of the device-side preparation before the user ever signs in. It is especially valuable for remote shipments, VIP devices, or app-heavy builds where a stockroom technician, OEM, or partner can stage the device first. In Zero Trust terms, pre-provisioning can improve consistency and time-to-productivity while still keeping the authoritative configuration in cloud identity and Intune policy.

## Implementation Guidance

1. Choose pre-provisioning only when there is a clear business reason. If standard user-driven mode already meets your timeline and support goals, adding technician flow may create unnecessary complexity.
2. Validate hardware support, including TPM attestation requirements and any reseller or warehouse process changes. Unsupported devices or unreliable network conditions will quickly undermine the technician phase.
3. Keep required device-targeted apps and policies lean so the technician flow completes consistently. Large or unreliable app sets cause most pre-provisioning delays.
4. Define who runs technician flow and where. Internal stockroom staff, partners, and OEMs all need documented responsibilities, network prerequisites, and packaging steps after the device is resealed.
5. Pilot both phases end to end. A successful technician flow is not enough; you must also confirm that the user flow remains fast, that late-arriving policies do not surprise the user, and that recovery steps are clear.
6. Monitor failure rates by hardware model, app bundle, and location so you can decide whether pre-provisioning is delivering enough value to keep using it.
