# 149: WIP for Enrolled

**Implementation Effort:** Medium — retiring legacy protection features is usually more organizationally difficult than technically difficult.

**User Impact:** Medium — changes to data-protection controls can affect user workflows, file handling, and business application behavior.

## Overview
Windows Information Protection (WIP) is no longer a strategic investment area and should not be used for new deployments. For organizations that still have WIP configured on enrolled Windows devices, the priority should be controlled retirement and migration to modern controls. A Zero Trust device strategy should rely on current capabilities such as Microsoft Purview information protection and DLP, Microsoft Edge for Business protections, BitLocker, Conditional Access, app control, and Microsoft Defender rather than expanding legacy WIP usage.

## Implementation Guidance
- Do not deploy WIP to new device populations. Treat any existing WIP usage as technical debt that needs an exit plan.
- Inventory where WIP is still enabled, which apps and identities are in scope, what data-protection outcomes it was meant to provide, and what business process dependencies remain.
- Map those outcomes to supported replacement controls such as Purview sensitivity labels, Endpoint DLP, browser-based data controls, compliant-device access, or other modern endpoint protections.
- Pilot the retirement path with a subset of users and confirm that protected-data workflows, save locations, print behavior, and file-sharing scenarios still meet business needs.
- Communicate clearly with affected users and support teams so they understand what changes, what protection replaces WIP, and how exceptions are handled during transition.
- Remove legacy policies in stages and keep rollback and evidence-capture procedures until the migration is complete.
