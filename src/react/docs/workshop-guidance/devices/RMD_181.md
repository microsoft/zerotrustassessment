# 181: Remote actions

**Implementation Effort:** Low to Medium  
**User Impact:** Medium

## Overview

Remote actions in Intune let administrators take targeted actions against managed devices without requiring a full remote-control session. For macOS, these actions can support incident response, troubleshooting, and device lifecycle operations when used by the right role at the right time.

In Zero Trust operations, remote actions are privileged operations. They should be limited to approved roles, performed from trusted admin workstations, and tied to a support or security workflow rather than used casually.

## Implementation Guidance

### Document the supported macOS actions
- Verify the currently supported Intune remote actions for macOS in your tenant before documenting them; the list can differ from Windows and can evolve over time.
- Commonly relevant actions include sync, restart, wipe, key rotation, diagnostics, and other lifecycle operations, but support should be confirmed against current product documentation.
- Map each action to an approval model so higher-impact actions such as wipe are not available to every support tier.

### Use remote actions deliberately
- Prefer the least disruptive action that solves the problem, such as sync or diagnostics before restart or wipe.
- Record the reason for the action in the ticket or incident workflow and communicate with the user when appropriate.
- Test each supported action on pilot devices so helpdesk staff understand user prompts, timing, and rollback expectations.

### Govern and review
- Limit remote action privileges using Intune RBAC and review role assignments regularly.
- Audit higher-risk actions such as wipe or key rotation to ensure they were performed appropriately.
- Review whether some support scenarios should use Remote Help instead of a more disruptive device action.
