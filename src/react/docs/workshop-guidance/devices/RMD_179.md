# 179: Certificates / Wi-Fi / VPN

**Implementation Effort:** High  
**User Impact:** Medium

## Overview

Certificates, Wi-Fi, and VPN profiles are foundational connectivity controls for managed macOS devices. When designed together, they can deliver certificate-based trust to corporate networks and reduce dependence on reusable passwords for device connectivity.

In a Zero Trust model, the goal is not simply automatic connectivity. The goal is to ensure that only managed, appropriately trusted devices can establish network access paths and that those paths align with compliance and identity controls.

## Implementation Guidance

### Design the certificate trust model
- Decide whether certificates will be issued from Microsoft Cloud PKI, an existing enterprise PKI, or another trusted source, and confirm which use cases each authority will support.
- Choose the authentication methods required for Wi-Fi and VPN, such as certificate-based authentication, and align them with network team requirements.
- Document certificate lifetimes, renewal behavior, revocation expectations, and dependencies on device identity or user identity.

### Build dependent profiles in Intune
- Create and test certificate profiles first, because Wi-Fi and VPN profiles often depend on the certificate being present and trusted.
- Create separate Wi-Fi and VPN profiles in Intune for distinct use cases, such as campus wireless, privileged admin access, or always-on remote connectivity.
- Pilot connectivity on representative networks before wide rollout so profile logic, trust chains, and DNS behavior can be validated.

### Operate and troubleshoot
- Monitor certificate issuance, profile deployment, and failed connection reports together instead of treating each as an isolated problem space.
- Coordinate certificate rollover and root trust changes carefully to avoid widespread connectivity loss.
- Review whether some access paths should move to modern app-layer access controls rather than remaining on broad network VPN access.
