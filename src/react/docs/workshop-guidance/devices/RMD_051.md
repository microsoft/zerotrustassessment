# 051: Mobile Threat Defense

**Implementation Effort:** Medium to High

**User Impact:** Low to Medium

## Overview
Mobile threat signals help organizations decide whether a device should be trusted to access organizational resources. In Microsoft Intune, threat data from Microsoft Defender for Endpoint or supported partner solutions can be incorporated into device compliance so that risky devices are blocked or remediated before they access Microsoft 365 and other protected apps.

This is a strong Zero Trust control because device trust is evaluated continuously, not assumed just because the device enrolled successfully once.

## Implementation Guidance
1. Choose the mobile threat signal source you will standardize on, such as **Microsoft Defender for Endpoint** or a supported partner.
2. Configure the relevant connector in the **Microsoft Intune admin center** and confirm the required licensing and administrator roles.
3. Deploy the mobile threat app or onboarding experience to the target platforms and ensure devices successfully report risk state.
4. Create or update **device compliance policies** so the device risk level must be at or below your accepted threshold.
5. Use **Conditional Access** to require a compliant device for access to Microsoft 365 and other sensitive services.
6. Define the operational process for false positives, incident triage, and user remediation so security and support teams know how devices return to compliance.
7. Periodically review which platforms and partner integrations are still supported, because the ecosystem changes over time.
