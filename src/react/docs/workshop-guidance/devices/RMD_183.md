# 183: Local account management

**Implementation Effort:** Medium  
**User Impact:** Medium

## Overview

Local account management on macOS should support the device lifecycle without undermining identity-based control. Most organizations need a consistent approach for the primary user account, support or break-glass accounts, and whether any standing local administrator rights remain on standard user devices.

In Zero Trust, the local account model matters because unmanaged administrator access or poorly governed secondary accounts can bypass the broader security design even when the device is enrolled and compliant.

## Implementation Guidance

### Define the local account model
- Decide whether standard users should receive local admin rights; the preferred pattern is usually no standing local admin for everyday users.
- Document which local accounts are required for support, recovery, or provisioning and how their passwords are controlled.
- Align the account strategy with Platform SSO, FileVault, and enrollment so the first-run experience remains supportable.

### Configure through Intune
- Use supported macOS account configuration settings in Intune to create or manage local accounts only where there is a clear business requirement.
- Avoid embedding reusable shared credentials in policy content unless the design explicitly addresses secret rotation and exposure risk.
- Pilot account creation, privilege level, and first sign-in behavior on test devices before production rollout.

### Review and reduce privilege over time
- Audit which users retain local admin rights and move recurring elevation needs to a more controlled model where possible.
- Coordinate password rotation and recovery processes with the service desk before using secondary admin accounts widely.
- Treat local account exceptions as temporary and review them regularly.
