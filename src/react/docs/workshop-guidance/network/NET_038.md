# Configure network content filtering with file policies (Preview)

**Implementation Effort:** Medium - Requires policy scope, acquisition, inspection, and application-owner coordination.  
**User Impact:** Medium - Broad file/text rules can disrupt applications, APIs, and legitimate uploads or downloads.

## Overview

Global Secure Access (GSA) content policies control supported file and text transfers to internet destinations, including generative AI applications and unmanaged cloud services. Basic Allow/Block rules restrict file MIME types and text types without requiring sensitive-data classification.

Scan with Purview adds Microsoft Purview data loss prevention (DLP) decisions to eligible traffic. This extends the shared network control from transfer-type restrictions to sensitive-content protection. It supports *Use least privilege access* by limiting data movement and *Assume breach* by reducing uncontrolled outbound channels.

AI workloads can use the existing network baseline rather than duplicate it. Their prerequisites and supported paths remain important: basic content filtering is not Purview inspection, malware scanning, or prompt-injection detection.

### Prerequisites

- Internet Access acquisition, intended user/group assignments, and Transport Layer Security (TLS) inspection.
- Internet Access licensing and the administrative roles for content policies, security profiles, and applicable Conditional Access assignments.
- Application-owner agreement on required and prohibited transfer types and destinations.
- The documented web-filtering prerequisite where rules use web categories as destinations.
- A Purview license and matching DLP policies when using Scan with Purview; basic Allow/Block rules do not require Purview.
- For AI scenarios, complete [AI network readiness](../AI/AI_163.md). [Purview network DLP for AI](../AI/AI_192.md) describes the additional sensitive-content requirements.

### Limitations

- Copilot Studio requires supported policies and its [baseline profile path](../AI/AI_027.md); availability in GSA does not establish support for every interaction.
- Broad JSON or HTML blocking can interrupt ordinary web and API traffic.
- File detection supports unencoded bodies and multipart encoding. Encoding files inside JSON or splitting transfers can prevent inspection.
- WebSocket traffic bypasses file-type filtering, although text content type is still evaluated.
- Applications can use multiple URLs and fully qualified domain names. Matching one destination does not establish coverage for every transfer path.
- Blocking a file type does not establish that allowed files are safe. Basic Allow/Block rules use GSA logs; Purview DLP alerts and Activity explorer apply to Scan with Purview.
- Scan with Purview requires eligible traffic mapped to an Entra user identity and remains subject to its documented inspection limits.
